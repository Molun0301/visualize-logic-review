# 逻辑图审查维护与发布

当前公开版：`1.0.0`。主分支 `main` 保存维护代码；标签 `vX.Y.Z` 表示可回退的版本。兼容修复增加修订号，新功能增加次版本，破坏兼容时增加主版本。

## 开发验证

```bash
python3 scripts/check.py
```

持续集成在每次推送与拉取请求时运行同一命令。测试使用临时目录或模拟接口，不要求个人账号。用户的配置、凭据、日志、统计快照和 `docs/开发文档` 不参与发布。

## 发新版本

1. 更新 `VERSION`、插件清单、包版本及运行时版本常量，保持一致。
2. 在 `docs/公开文档/更新记录.md` 写明行为变化、兼容性及迁移步骤，更新 `发布说明.md`。
3. 运行 `python3 scripts/check.py`，检查 `git diff --check` 和待提交文件。
4. 提交后创建标签，再推送。标签推送通过自动检查后生成压缩包、校验摘要和 GitHub 发布页。

```bash
git add .
git commit -m "发布：说明本次实际改动"
git tag vX.Y.Z
git push origin main
git push origin vX.Y.Z
```

仓库配置了 `.gitignore` 和 `.gitattributes` 排除本地开发文档。不要强行添加私密文件。离线打包可运行 `python3 scripts/package.py`，产物在 `dist/`，按已提交版本打包。

## 更新与回退

具体安装命令见仓库首页。使用默认分支的用户先 `git pull --ff-only`，再重复安装命令；使用固定版本的用户执行 `git fetch origin --tags`，随后 `git checkout vX.Y.Z` 并重复安装。回退也使用该流程，运行数据保留。源码目录存在未提交改动时先自行保存，避免混入升级。

安装记录用于区分插件文件和用户文件。文件被手动改过时，升级会提示冲突；确认替换可传 `--replace`。卸载只移除仍与安装记录一致的文件，用户改过的文件会保留并报告。

问题反馈请使用本仓库 Issues（问题跟踪），附插件版本、宿主版本、操作系统及脱敏复现步骤。
